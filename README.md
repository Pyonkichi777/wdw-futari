# ぞうたんフロリダ上陸ツアー

2027年5月のフロリダ・ディズニー旅行に向けた、夫婦2人用の作戦帳アプリ（PWA）。

- 公開URL: https://pyonkichi777.github.io/wdw-futari/
- iPhoneでは Safari で開き、「共有」→「ホーム画面に追加」でアプリのように使えます

## いまできること（Phase 1）
- **図鑑**: 4パークの主なアトラクション（身長制限・激しさ・優先パスの種類など）
- **投票**: 2人がそれぞれ「絶対乗る／乗りたい／どちらでも／乗らない」をつける。相手の回答は、自分が全部答えると見える
- **合意リスト**: 投票から S（何があっても乗る）／A（なるべく）／B（乗れたら）を作り、2人で並べ替えて確定

## 開発
```
npm ci
npm run dev     # 開発サーバー
npm test        # テスト
npm run build   # 型チェック＋本番ビルド
npm run test:offline # ビルド済みのアプリ本体を通信断条件で検証
```

## 予約・共有・更新

- 食事は取得した予約時刻、パスは取得した到着枠の開始・終了を入力して「保存」。以前の単一時刻も読めますが、終了は推測しません。
- 予約チェックを外しても入力した枠は保持します。チェックを外している間は作戦の固定時刻に使いません。
- 共有作戦の変更・復元と予約時刻の保存には通信が必要です。相手が更新した作戦・取得枠への古い入力は保存せず、再確認を案内します。通信できないときは閲覧・文字の控えを使ってください。
- アプリ上部に版を表示します。新しい版は利用者が切り替えます。入力途中・保存中は再読込を保護します。
- 作戦の保存・復元には日割りや余裕時間が含まれます。取得した予約時刻・枠は予約チェック側に残り、復元で巻き戻りません。

検証の手順・結果・未確認の範囲は [改修と検証の記録](docs/readiness-v3.md) を参照してください。

### 本番データを使わない画面確認

```sh
VITE_DEMO_MODE=true npm run dev -- --host 127.0.0.1 --port 4173
```

`http://127.0.0.1:4173/wdw-futari/tools/ui-review.html` を開きます。初回だけ架空の投票・作戦を端末内に作ります。Firebaseへは接続しません。通常の本番ビルドでは環境変数を指定しないでください。この検証ページは公開用ビルドの入口には含まれません。
