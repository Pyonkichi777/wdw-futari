# 改善計画v3に対する改修と検証

実施日：2026-10-25。公開ソースと承認済みの改善計画v3.0を対象に実装した。実際の旅行データへのテスト入力は行わない。

## 変更

| 計画 | 対応 |
| --- | --- |
| R01 | 食事の単一予約時刻と、パスの開始・終了の到着枠を分離。保存ボタンで一括確定。旧形式を保持し、終了を推測しない。到着が枠の開始後でも終了までなら利用可能として計算。終了超過は警告し、取得枠を動かさない。 |
| R02 | 日付ボタン・保存した作戦の概要・文字の控えを、実際に予定があるパークと最初の時間帯から表示。予定がなければ「予定なし」。 |
| R03 | ビルドごとに版と更新確認用ファイルを生成。アプリ本体を事前保存するService Workerに変更。新しい版を通知し、利用者が切り替える。予約入力の下書き・保存名・実行中の保存は再読込から保護。 |
| R04 | 準備・予約購入・任意の残数と総数を明記。フィルターは準備を除く予約購入の件数と説明。 |
| T01 | 取得枠の終了ちょうど／1分後、前の枠を最後に使う場合、固定した食事への遅れ、最初の予約に合わせた到着を検証。 |
| T02 | 控えに版・日時・取得枠・仮置き注記を含める。作成後の予定変更は控えに反映しない。生成済みアプリ本体の通信断での読出しを通信代替で検証。 |
| T03 | 通信失敗時に古い作戦全体を送信待ちにする経路を削除。確認した版と最新が違う場合は変更・復元を中止。取得枠も入力中の他画面更新と保存直前の競合を検知。予約チェック解除時は取得枠を保持。 |

通信断で共有作戦を編集する機能は、全体上書きによる消失を防ぐため停止した。接続復帰後に最新の作戦を確認して再操作する。閲覧・文字の控えは引き続き利用できる。

## 自動検証

`npm test`、`npm run build`、`npm run test:offline` を実行する。CIの公開前チェックにもオフライン検証を追加した。

- 既存の196テストを維持し、取得枠・互換性・競合・復元・文字の控え・再読込保護の回帰テストを追加。
- 実行結果：42ファイル・212テスト成功、型チェックを含む本番ビルド成功、生成したService Workerのオフライン検証成功。
- Firestoreの通信代替で、通信失敗・作戦の競合・取得枠の競合で書き込まないことを確認。本番Firestoreへは接続しない。
- ビルド済みService Workerを読み込み、アプリ本体の保存成功後に通信を停止してHTML・JS・CSSを取得。自動切替をせず手動通知で切り替えること、別アプリのキャッシュを削除しないことも確認。

## ブラウザでの確認

ローカルのお試しデータを使用。Chrome、幅390pxの画面で確認した。

- 開始のみでは保存不可、開始・終了を揃えると保存可能。保存枠を画面に表示。
- 別のローカル画面で同じ予約を変更すると、入力途中の画面に競合を表示して保存を止める。
- 日付ボタンが朝の設定に引きずられず「夕 マジック」を表示。
- 小さい時刻入力欄にチェックボックス用CSSがかかっていたため修正。44px以上の高さで時刻を読める。画面の横はみ出しなし。
- ローカルの本番形式ビルドを更新し、旧画面へ新しい版を通知。入力中は切替ボタンが無効、入力を戻すと切替可能。切替後の版更新と保存枠の保持を確認。
- 取得済みチェックの解除後も枠が残り、残件数が戻ることを確認。

## 残る実端末確認

以下は未確認であり、上記の自動テストと同じものとして合格扱いにしない。

- 2台のスマホから本番Firestoreへ接続した同時編集、通信断からの復帰。
- iPhoneのホーム画面からの再起動、認証切れ、保存容量不足。
- 実端末でファイルに保存した文字控えの読み出し、共有先アプリの挙動。ローカルブラウザでファイル保存を試した際に操作がタイムアウトしたため、保存成功とは扱わない。文字列の生成内容は自動テストで確認。
- 旧版を長時間開いた実端末での切替と、旧クライアントが残っている間の表示。新しい到着枠・解除状態を正しく読むには両方を最新版へ切り替える。

取得枠は同日内の開始・終了を扱う。深夜をまたぐ枠には未対応。営業時間・ショー時刻・予約条件の将来の変更は別途確認する。
